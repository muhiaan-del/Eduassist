## 1. Core Goal of the App

EduAssist is an institutional AI-powered Learning Management System (LMS) designed for universities and colleges.

The core problem it solves is that traditional LMS platforms such as Moodle and Canvas are passive repositories. They store files but do not actively teach. Lecturers spend hours manually creating quizzes and answering repetitive student questions. Students turn to generic AI tools such as ChatGPT, which hallucinate and are not tied to their specific syllabus.

The solution is an AI layer that sits on top of the institution's actual teaching materials. It is:

- **Curriculum-grounded** — answers only from lecturer-uploaded documents.
- **Lecturer-controlled** — human-in-the-loop before content reaches students.
- **Measurable** — provides analytics on student performance.

---

## 2. Key Decisions and Reasoning

| Decision | Reasoning |
|----------|-----------|
| Institutional (multi-tenant) architecture | The buyer is the university, not the student. The app enforces a strict hierarchy: Admin, Faculty, Course, Unit, Class, Student. This mirrors real university org charts and allows the institution to provision and control all users. |
| Curriculum-grounded RAG (Retrieval-Augmented Generation) | Generic AI hallucinates. By using vector search (pgvector) to retrieve only the most relevant chunks from the lecturer's uploaded materials, the AI is constrained to factual course content. This is the single most important feature for institutional trust. |
| Human-in-the-loop (HITL) review | Lecturers must manually review and publish quiz questions and study notes generated by the AI before students see them. Faculty retain control, which is critical for adoption. |
| Local OCR (Tesseract.js) | The initial version used Groq Vision for OCR, but it hit strict rate limits (8,000 TPM) and was costly. Switching to Tesseract.js made OCR free, offline, and unlimited, removing a major bottleneck. |
| Manual quiz builder over AI quiz generation | The AI quiz generator was brittle due to network timeouts, model refusals on sensitive content, and JSON parsing failures. It was shelved in favor of a reliable manual builder where lecturers type questions directly. This completed the assessment loop with zero dependencies. |
| LiveKit for live audio | WebRTC requires a complex media server. Building one from scratch is impractical. LiveKit Cloud offers a free tier with 100 concurrent connections and handles all STUN, TURN, and ICE complexity for one-way audio broadcasts. |

## 3. Constraints, Rules, and Preferences Established

- **Tech Stack:** Next.js 16 (App Router), Supabase (Postgres, Auth, RLS), Tailwind CSS 4, Groq API (LLMs), LiveKit Cloud (Audio).
- **Turbopack vs Webpack:** The project runs on Turbopack by default. Switching to Webpack breaks the Tailwind CSS 4 pipeline. Streaming errors are fixed by wrapping client components in Suspense, not by switching bundlers.
- **Environment Variables:** All secrets (Supabase keys, Groq API key, LiveKit keys) must live in `.env.local` locally and in Vercel Environment Variables in production. They must never be committed to Git.
- **Database Security:** Row Level Security (RLS) is enabled on all tables. The backend uses the `SUPABASE_SERVICE_ROLE_KEY` to bypass RLS for secure admin operations such as provisioning users or inserting questions.
- **Chunking and Embeddings:** Uploads are split into approximately 500-character chunks. Embeddings are generated locally using the Xenova Transformers library with the gte-small model to avoid API costs. Chunks are inserted in batches of 20 to avoid Cloudflare connection timeouts.

## 4. Current State of the Work

### 4.1 Completed Features (V1.0)

| Feature | Status |
|---------|--------|
| Authentication and Roles | Domain-based login with Admin, Faculty, and Student roles. |
| Institutional Hierarchy | Admin provisions Faculty, creates Courses, Units, and Classes, and admits Students. |
| Material Upload | Supports PDF, Image, Scanned PDF via Tesseract OCR, and plain Text. |
| Vector Search | pgvector integration for semantic retrieval from materials. |
| AI Chat | Includes memory, citations, and follow-up suggestions grounded in materials. |
| Study Notes and Flashcards | Generated by AI from materials and saveable by students. |
| Manual Quiz Builder | Faculty creates questions, saves them as drafts, and publishes them to students. |
| Quiz Attempts | Student answers are saved and scored. |
| Analytics | Faculty see class averages and weak questions. Students see their progress history. |
| Messaging | One-on-one chat between Faculty and Student, with an AI Copilot draft feature for the Faculty. |
| Announcements | Faculty broadcast to the class. |
| Live Audio | Faculty broadcast audio. Students see a Live Now banner and can join. |
| Deployment | Successfully deployed to Vercel over HTTPS. |

### 4.2 Unaccomplished Features and Known Issues

| Feature or Issue | Reason |
|------------------|--------|
| AI Quiz Generation | Shelved. The Groq API was unstable due to rate limits, PII refusals, and JSON parsing failures. The manual quiz builder replaced it for reliability. |
| Email Invitations | The app uses Supabase's default email service, which only sends to authorized team members. To email real students, Custom SMTP such as Resend or Brevo must be configured in Supabase. |
| Large PDF Timeouts | Uploading a PDF of 400 pages or more takes about 90 seconds. Vercel's serverless function timeout can kill this. It needs to be moved to a background job such as Vercel Workflows. |
| Live Audio Auto-End | When the Faculty closes their tab, the session stays live in the database. A webhook is needed to automatically set status to ended. |
| Vercel Login Issues | The live URL is https://eduassist-ai-c.vercel.app, but Supabase Auth URL settings still point to localhost. This must be updated in the Supabase Dashboard for login to work on the live site. |
| Rate Limiting | The Groq API routes `/api/ask` and `/api/generate-notes` are not rate-limited. A single user spamming the chat could exhaust the free API tier. |

## 5. Future Development (V2.0 Roadmap)

To move from a successful pilot to a scalable commercial product, the following phases are recommended.

### 5.1 Production Hardening and Pilot Onboarding

- Configure Custom SMTP by integrating Resend or Brevo in Supabase to enable real email invites.
- Fix Vercel and Supabase Auth URLs by updating the live URL in Supabase settings.
- Implement rate limiting using the universal-rate-limit library on all AI endpoints to prevent API abuse.
- Move PDF chunking and embedding to a background task to avoid Vercel timeouts.

### 5.2 Advanced AI Features

- Revisit AI quiz drafting by adding an optional Suggest Question button using a more stable model as a helper, while keeping the manual builder as the primary flow.
- Add multimodal chat so students can upload photos of homework problems directly into the AI chat, not just as course materials.

### 5.3 Institutional Scale

- Add SSO integration so universities can log in using their existing institutional accounts such as Google Workspace or Microsoft Entra.
- Add subdomain routing so that `techuniversity.eduassist.app` automatically loads the correct institution's branding and login page.
- Upgrade live audio to support two-way audio, live transcription, and automatic session recording for revision.

### 5.4 Analytics and Reporting

- Build an Institution Dashboard that gives the Admin a high-level view of adoption, including how many lecturers are active and how many students use the AI.
- Add exportable reports so Faculty can download quiz results as CSV for their own records.

---

## 6. Final Note

The app is currently in a strong, functional pilot state. The core loop of Upload, Learn, Assess, Analyze, and Broadcast works.

The priority for V2 is not adding more features, but hardening what exists through SMTP, rate limits, and background jobs so it can be handed to a real university with confidence.
